## 3. Comportamiento implementado

1. **Rol IT separado**
   - Accede solo al panel **👥 Gestión de Usuarios**.
   - No ve dashboard, firmas, vigencia ni feriados.
   - La autorización se revalida contra la base: solo un usuario IT vigente
     puede ejecutar las operaciones.
2. **Listado**
   - Muestra ID, nombre, correo registrado, rol, vigencia, última actividad y
     días de vacaciones asignados, usados y disponibles del año.
3. **Alta**
   - Nombre, correo (cualquier dominio válido), rol, días de vacaciones y
     contraseña inicial.
   - El correo se normaliza a minúsculas y no puede repetirse (comparación sin
     distinguir mayúsculas).
4. **Edición**
   - Nombre, correo, rol y días de vacaciones.
   - Un usuario no puede cambiarse el rol a sí mismo.
5. **Baja lógica y reactivación**
   - No se borra el historial.
   - Nadie puede desactivar su propia cuenta.
   - No se puede desactivar al único Administrador o IT activo.
   - Al reactivar se actualiza `ultima_actividad` para que la vigencia no lo dé
     de baja de inmediato.
6. **Reseteo de contraseña**
   - PBKDF2-SHA256, mínimo 8 caracteres, con al menos una letra y un número.
7. **Auditoría**
   - `usuario_log`: fecha, ejecutor, afectado, acción (`CREACION`, `EDICION`,
     `BAJA`, `REACTIVACION`, `RESET_PASSWORD`) y detalle.
   - Se escribe en la misma transacción que la operación.
8. **Vigencia**
   - IT queda protegido de la baja automática semestral, igual que Gerencia.

**Flujo real con AppTest**

- El panel IT renderiza las pestañas **Usuarios**, **Crear usuario** y
  **Auditoría** sin excepciones.
- Se creó una cuenta desde el formulario: «Usuario creado con id 527» y la fila
  apareció en la base con los días asignados.
- La cuenta y su registro de auditoría se eliminaron después; la base quedó
  limpia.

**Estado de la base al cierre**

| Tabla | Filas |
|---|---|
| `rol` | 5 (Consultor, Administrador, Coordinador GTC, Contabilidad, IT) |
| `usuario` | 7 (6 previos + cuenta IT de prueba) |
| `solicitud` | 2 (sin cambios) |
| `solicitud_historial` | 3 (sin cambios) |
| `usuario_log` | 0 (las pruebas limpian sus datos) |
| `recordatorio` | 0 |
| `vigencia_log` | 0 |

**Limpieza:** cada prueba crea su ejecutor IT y sus usuarios temporales, y los
elimina junto con sus filas de `usuario_log`. El smoke test no deja residuos.
